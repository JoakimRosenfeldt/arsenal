# Music recommendations

Arsenal uses [Jev Latest](https://openrouter.ai/~typesafe/jev-latest) through OpenRouter to suggest tracks from the imported Rekordbox library. Add an OpenRouter API key under Preferences → Music recommendations. Existing encrypted OpenRouter keys in `userData/ai-settings.json` are reused. Keys stay in the main process after saving and use the operating system's encryption when available; otherwise they last only for the current session.

Preferences → Library sets a minimum song length, defaulting to 30 seconds. Tracks below that length are excluded from the library, searches, playlists, smart playlist rules, duplicate scans and suggestions. Tracks with an unknown duration remain included. Set the minimum to 0 to include all tracks. The setting is saved across restarts and updates open windows immediately. Hidden tracks remain in the source XML and reappear when the minimum is lowered.

Suggestions use a description, selected starting tracks, or both. All selected starting tracks are included, subject to the request byte budget. Arsenal sends the description and bounded music metadata to OpenRouter and TypeSafe: title, artist, genre, album, mix, remixer, BPM, key and year. It sends no audio, file paths, artwork URLs or library track IDs. Streaming tracks and tracks with unavailable audio can be suggested. Metadata matching cannot verify how a recording sounds, and sparse metadata can produce weak matches.

Song metadata uses rows with one shared column header per request: title, artist, genre, BPM, musical key, album, mix, remixer and year. Starting tracks use the first five columns. Missing values within rows use `null`; trailing missing values are omitted. Repeated whitespace is collapsed. Mix names already present as a full phrase in the transmitted title are omitted, ignoring letter case. Each question points to its candidate row by a zero-based index. Shared scoring instructions appear once in the request state; each candidate question references them and carries a concise five-level rubric.

Jev uses the [OpenRouter decisions API](https://openrouter.ai/docs/api/api-reference/alphadecisions/submit-a-decisions-questions-and-answers-request), not chat completions. Requests go to `https://openrouter.ai/api/alpha/decisions` with model `~typesafe/jev-latest`. Each candidate gets an independent `score` question with five levels: unrelated style and opposite mood; partial fit with a defining conflict; plausible fit with unknown details; style, mood and energy fit with minor differences; exact requested sound with no evident mismatch. Jev returns a fractional score from 0 to 4 and confidence from 0 to 1. Arsenal maps the match to 1–100 with `1 + 99 * score / 4` and excludes matches below 67 before weighting.

The internal ranking score is `1 + (matchScore - 1) * confidence`, equivalent to `1 + 99 * (score / 4) * confidence`. It stays between 1 and 100 and keeps full precision for sorting. A more certain match can outrank a stronger but less certain match. The UI shows only Jev's confidence on a 0–100% scale, rounded to a whole percent: `0.95` is displayed as `95% confidence`. The weighted ranking score is not displayed. [Jev's confidence](https://docs.typesafe.ai/confidence) describes how concentrated its answer probabilities are, not the probability that a listener will like a track. Arsenal validates every requested score and confidence and maps them back to a supplied candidate; missing, malformed or out-of-range values reject the result. Jev does not generate track names or explanations.

Every request is limited to 80,000 UTF-8 bytes for the complete serialized JSON body, including the model, description, seed metadata, candidate metadata, instructions and criteria. Byte size is not a token count, so this cap does not guarantee a request fits Jev's 32k context. If OpenRouter reports an input-size or context-limit error, Arsenal halves the candidate batch and retries the same tracks. Later batches keep the reduced size; a single-track batch that still exceeds the limit returns an error. Metadata fields are shortened before serialization. Batches fit as many candidates as the byte budget allows, with no fixed candidate-count cap. All eligible tracks are scored across batches; the library is not cut off at the first batch. If even one candidate cannot fit, Arsenal returns an input-limit error without sending that request.

The playlist contains up to 12 suggestions, excludes selected tracks, and limits each artist to two suggestions. Suggestions are sorted by their full-precision weighted score, highest first. Equal weighted scores use higher confidence, then track ID as a stable tie-breaker. Explanations describe metadata matching and any tempo or key match calculated locally; these labels do not change the score or order.

Explicit BPM ranges use Rekordbox metadata. `124-128 BPM` includes both endpoints. `Under 128 BPM` excludes 128, while `at most 128 BPM` includes it. A single target such as `128 BPM` allows three BPM on either side. Tracks without BPM metadata cannot pass a BPM filter. Valid tempos are 30 to 300 BPM.

Requests require an internet connection and OpenRouter credits. Progress reports how many tracks have been scored. Cancellation, library replacement and window closure abort the active request. Each batch has a 45-second timeout and the entire operation has a five-minute deadline. Failed operations return an error rather than a partial playlist. Failures show the HTTP status and a bounded, redacted provider message in the app and debug log. Connection failures include the network error code when available. Debug logs also include batch sizes, byte counts and reported input-token usage; they omit API keys and full request or response bodies.
