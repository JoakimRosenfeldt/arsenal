# Music recommendations

Arsenal uses [Jev Latest](https://openrouter.ai/~typesafe/jev-latest) through OpenRouter to suggest tracks from the imported Rekordbox library. Add an OpenRouter API key under Preferences → Music recommendations. Existing encrypted OpenRouter keys in `userData/ai-settings.json` are reused. Keys stay in the main process after saving and use the operating system's encryption when available; otherwise they last only for the current session.

Suggestions use a description, up to 20 starting tracks, or both. Arsenal sends the description and bounded music metadata to OpenRouter and TypeSafe: title, artist, genre, album, mix, remixer, label, comments, BPM, key and year. It sends no audio, file paths, artwork URLs or library track IDs. Streaming tracks and tracks with unavailable audio can be suggested. Metadata matching cannot verify how a recording sounds, and sparse metadata can produce weak matches.

Jev uses the [OpenRouter decisions API](https://openrouter.ai/docs/api/api-reference/alphadecisions/submit-a-decisions-questions-and-answers-request), not chat completions. Requests go to `https://openrouter.ai/api/alpha/decisions` with model `~typesafe/jev-latest`. Each candidate gets an independent `score` question on a four-level rubric, from conflicting with the requested mood to closely matching it. Scores below 2 are omitted. Arsenal validates every requested score and maps it back to a supplied candidate; missing, malformed or out-of-range scores reject the result. Jev does not generate track names or explanations.

Every request is limited to 24,000 UTF-8 bytes for the complete serialized JSON body, including the model, description, seed metadata, candidate metadata, instructions and criteria. This conservatively budgets one token per byte and leaves 8,000 tokens below Jev's 32k input limit for provider formatting and overhead. Metadata fields are shortened before serialization. Batches contain at most 40 candidates and shrink to fit the byte budget. All eligible tracks are scored across batches; the library is not cut off at the first batch. If even one candidate cannot fit, Arsenal returns an input-limit error without sending that request.

The playlist contains up to 12 suggestions, excludes selected tracks, and limits each artist to two suggestions. Higher Jev scores rank first, with small tempo and harmonic-key bonuses and an artist-repeat penalty. Explanations describe metadata matching and any tempo or key match calculated locally.

Explicit BPM ranges use Rekordbox metadata. `124-128 BPM` includes both endpoints. `Under 128 BPM` excludes 128, while `at most 128 BPM` includes it. A single target such as `128 BPM` allows three BPM on either side. Tracks without BPM metadata cannot pass a BPM filter. Valid tempos are 30 to 300 BPM.

Requests require an internet connection and OpenRouter credits. Progress reports how many tracks have been scored. Cancellation, library replacement and window closure abort the active request. Each batch has a 45-second timeout and the entire operation has a five-minute deadline. Failed operations return an error rather than a partial playlist. Debug logs include batch sizes, byte counts, reported input-token usage and HTTP status; they omit API keys, metadata and raw responses.
